# Clan 26.05

Stable release. Track the matching stable `nixpkgs` branch. Read Upgrade and Breaking Changes before bumping `clan-core`.

## Highlights

- `clan machines update` registers the new generation in the bootloader before live activation, so it survives a reboot even if activation fails. A blocked activation now reports the cause and instructs reboot; previously it failed twice with an opaque error. `--no-check` bypasses inhibitors when safe.
- `clan machines update --specialisation <name>` activates a named NixOS specialisation instead of the default system.
- Interactive `vars` prompts retain previous values by default; `--regenerate` requests a new value. This prevents Enter from clearing secrets and fixes multiline-input bugs.
- ZeroTier machine IPs are detected automatically; `targetHost` is no longer needed for mesh access. Multiple networks per clan are supported, requiring migration.
- Experimental `p2p-ssh-iroh` provides NAT-traversing SSH over encrypted QUIC, without port forwarding or VPN. It is commented out in default templates. Iroh is for operator management traffic (`clan machines update`); a mesh VPN remains the service-to-service network.
- `forwardAgent` forwards the SSH agent to managed machines; available at `clan.core.networking` and inventory `deploy`; default disabled.

## Upgrade

```nix
inputs.clan-core.url = "https://git.clan.lol/clan/clan-core/archive/26.05.tar.gz";
inputs.nixpkgs.follows = "clan-core/nixpkgs";
```

If using ZeroTier, follow `../guides/migrations/zerotier.md` before upgrading. Upgrade one non-critical machine first, preferably with fallback SSH not routed through ZeroTier. Avoid unrelated edits; keep changes minimal for diagnosis.

## Breaking changes

### ZeroTier

ZeroTier now supports multiple instances; network IDs and machine IPs are coupled to instance name. `clan.core.networking.zerotier.*` is removed. Existing setups require migration; follow `../guides/migrations/zerotier.md` before upgrading.

### sshd host certificates

`sshd` enables CA-signed host certificates by default and always uses `meta.domain` from `clan.nix` as certificate search domain. `certificate.searchDomains` is no longer required to set up the CA. The `openssh-ca` generator now exists for every clan using `sshd`; first upgrade may report:

`File 'id_ed25519.pub' of generator 'openssh-ca' does not exist.`

Fix: run `clan vars generate`, then deploy.

### CLI removals/replacements

- `clan flakes create my-clan` → `clan init my-clan`; `clan init` interactively guides creation.
- Removed `clan vms run`, `clan vms inspect`, `vm` as `clan machines build --format` value, and the `vm` vars backend.
- `clan machines build` adds `--no-secrets`, `--no-sandbox`, `--system`.
- `clan vars check` and `clan vars fix` accept zero or more machines; no machine means every clan machine.

### Upstream NixOS changes

- **systemd stage-1 initrd is default** in NixOS 26.05; scripted initrd is deprecated and removed in 26.11. This is high risk for remote/headless machines because an error may appear only after reboot. Most incompatibilities become evaluation assertions, but these do not:
  - LUKS root: `fileSystems."/".device` MUST be `/dev/mapper/<name>`, with `<name>` matching `boot.initrd.luks.devices.<name>`, or systemd waits indefinitely for the passphrase and the machine never boots. For LVM-on-LUKS and similar setups, add `"x-systemd.device-timeout=infinity"` to `fileSystems."/".options` instead.
  - Remote SSH unlock: `cryptsetup-askpass` is removed; use `systemctl default`, which prompts as needed. When piping a passphrase over SSH, use `ssh -o RequestTTY=force` so it receives a TTY.
  - `/dev/root` is removed; replace `fileSystems` references with stable `/dev/disk/by-uuid/...`, `/dev/disk/by-label/...`, or matching `/dev/mapper/...` paths.
  - Some kernel command-line parameters were renamed to native systemd equivalents.
  - Temporary fallback: `boot.initrd.systemd.enable = false` (discouraged; scripted initrd removed in 26.11).
- **D-Bus default:** `dbus` → `dbus-broker`. Restarting D-Bus mid-session is unsafe, so the first `clan machines update` after upgrade is expected to fail during live activation. This is not deployment failure: the generation is bootloader-registered; reboot to apply it. Retain old daemon with `services.dbus.implementation = "dbus";`.
- **Kernel:** 6.12 → 6.18; expect hardware, driver, and out-of-tree-module regressions. `reiserfs` and `ecryptfs` are unavailable (`reiserfs` was removed in Linux 6.13). Clan's installer tracks the latest ZFS-compatible kernel.
- **`fileSystems.<name>.fsType`:** mandatory; no default. Disko and Clan templates set it, but hand-written entries MUST specify `fsType`.
- **`networking.resolvconf.enable`:** default `true` (previously conditional on `environment.etc."resolv.conf"`). If defining `environment.etc."resolv.conf"`, also set `networking.resolvconf.enable = false`.

### Darwin

`x86_64-darwin` support is removed and ends after 26.05 in `nixpkgs`; `aarch64-darwin` remains supported. Intel-Mac users must pin to `25.11` or migrate before upgrading.

## Community and core services

`coredns` moved from `clan-core` to `clan-community`.

New `clan-core` services: `dm-dns` (data-mesher DNS), `ncps` (Nix binary-cache proxy), `pki` (static certificates), experimental `p2p-ssh-iroh` (iroh SSH), experimental `installer` (installation image).

New `clan-community` services: `authelia`, `desktop`, `dm-pull-deploy`, `dm-wireguard-star`, `localsend`, `mosquito`, `punchcard`, `webapps`, `wireguard-star`.

## Vars backends and recipients

Backends: `age` added (experimental); `fs` and `vm` removed. All `clan.core.vars` changes in this release, including `recipients` and `age.secretLocation`, are experimental, subject to change, and have no guaranteed migration.

`vars.settings.recipients`, available on both `clan.core` and the flake, declares who may decrypt generated secrets and controls secret access across the clan. It is likely to be refactored next release; interface changes have no guaranteed migration.

## Templates

### Disk

`disko/single-disk` → `disko/ext4-single-disk`. Added:
- `disko/btrfs-single-disk-subvolumes`: single disk, Btrfs subvolumes, automated btrbk snapshots
- `disko/btrfs-single-disk-subvolumes-impermanance-rollback`: Btrfs subvolumes, Btrfs ephemeral-root rollback, automated btrbk snapshots
- `disko/btrfs-single-disk-subvolumes-impermanance-tmpfs`: Btrfs subvolumes, ephemeral tmpfs root, automated btrbk snapshots
- `disko/ext4-single-disk`: classic GPT with ext4 root; renamed from `disko/single-disk`

Removed: `disko/single-disk` (renamed to `disko/ext4-single-disk`).

### Machine

Removed: `machine/demo-template`, `machine/test-morph-template`.

### Clan

Modernized and integrated with `../getting-started/quick-start.md` and `clan-cli`. Starter inventory now includes `sshd`, `users`, `p2p-ssh-iroh`, `installer`; `admin`, `zerotier`, `tor` removed. Magic placeholders: `{{name}}`, `{{domain}}`. `x86_64-darwin` removed from default `systems`.

## `clan.core.clanPkgs`

Only `zerotier-members` and `zerotierone` remain; most packages were never intended for downstream use. `clanPkgs` will be removed next release.
